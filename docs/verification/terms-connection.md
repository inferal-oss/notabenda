# Terms connection inspection verification

Requirement: `REQ-PRODUCT-TERMS-CONNECTION`.

The optional public entry compares actual terms controllers with complete normalized expected offers and an optional host operation. Tests cover changed statement/action/document metadata under an unchanged offer ID, complete selected localization changes, preview offers, custom controllers without a comparator, independent browser bundles, SSR imports and strict installed types. Comparator output is explicitly a local host assertion, not authenticated factory provenance or backend authorization.

Actual controller scenarios cover idle and checked states, a preexisting recovery key, pending submission, confirmed receipt, a server save followed by lost acknowledgement, stale/retired/invalid-receipt errors and destruction retaining receipt state. The lost-acknowledgement scenario independently confirms the server record exists while the controller has no confirmed receipt. Inspection causes no submission, retry, subscription, checkbox edit or destruction; controller state and retained backend data remain unchanged.

The fixed report projection excludes operation/request/receipt identifiers and authored or translated wording. Malformed descriptors, accessors, executable options, cycles, oversized references, hostile snapshots and throwing custom methods produce generic errors without rejected values. Publication, active backend selection and application behavior remain explicitly unchecked in every state. Local matches never mark a pack installed or legally sufficient.

The English light and midnight examples load a standalone inspection bundle only after a deliberate request. Their semantic UI invalidates old results and revokes downloads on state changes or disposal. Accessibility checks cover named controls, status and observation lists; native layout, contrast, real host authorization and application behavior require separate verification. Framework adapters use the same host-owned controller API; the example inspection panel does not alter framework lifecycle or offer compilation.

Local Chromium checks used the isolated demo Worker: inspection left the checkbox unchecked and produced no agreement POST; checking the box cleared the snapshot, explicit sample submission produced one acknowledged POST, and reinspection reported the historical controller confirmation while leaving publication/backend activation and application behavior unchecked. Desktop, midnight and mobile checks are recorded separately from adopter acceptance.
