## 23 October: original byte copying

A synthetic `Uint8Array` reproduced an input-boundary defect: the prior copy and hash routines called an input's custom iterator, allowing it to substitute different bytes. Bounds checks also read shadowed length/buffer properties. These are host-supplied value cases, not a demonstrated remote exploit or an adapter-code sandbox escape.

The shared original-file helper now checks actual typed-array length and an ordinary backing buffer through intrinsic getters, then copies indexed bytes with the native typed-array constructor. Caller getters, iterators, constructors and species are not consulted. Empty, oversized, shared, detached, non-byte and proxy values are rejected; positive safe-integer copy limits are required. Subarray offsets, ordinary subclasses and Node buffers retain their actual indexed bytes. Hashing, blob sealing/reconstruction and separately authorized admin originals use the same owned representation. A stored chunk is detached before its hash is awaited; sealing also owns the input before its first await. Admin copies are bounded by the retained file's declared size before allocation, then checked for exact length and SHA-256.

The 35 focused byte/order/confirmation tests passed on Node 22. Three new byte-level tests and two archival/admin integration tests all fail against the previous verified Cloudflare archive. They cover inert hostile properties, real byte limits, ownership across awaited storage, chunk reconstruction, mismatch rejection before publication, exact image/download bytes and refusal before private file reads. Existing corruption, transaction rollback and per-request archive permissions remain exercised. A TypeScript check caught an overly broad backing-buffer return type during this work; the corrected helper explicitly returns an owned `Uint8Array<ArrayBuffer>`. This is selected data-integrity evidence, not complete security review, authenticity, legal sufficiency or production provider acceptance.
