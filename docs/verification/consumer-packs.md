# Consumer pack verification

Requirement: `REQ-PRODUCT-CONSUMER-PACKS`.

The consumer-pack suite exercises all five independent targets, focused questions, preserved original pins, no inferred profiles or host fields, business-audience review, fixed profile-language advice, separate guarantee branches and the exact confirmation admission dependency. Old questionnaire reports resume with new facts unknown. Contradictory charge/payment answers remain visible; imported facts and restrictions are preserved. Private justifications stay in the report, while builder/host work appears in the matching connection brief. Forged saved input reviews are discarded and regenerated.

The shared connection suite mounts every installed pack and compares its real tasks/checks to the target contract, with network and persistence effects forbidden. CLI tests run selection, draft generation and resume. Existing contract-action, dispatch, paid-order, confirmation and guarantee suites verify the component behavior and failure states, rather than treating pack selection as an end-to-end implementation. Site tests check the five visible groups, every direct card target and linked example/guide.

Actual applicability, truthful inputs, public-route accessibility, payment/formation behavior, provider delivery, artifact legibility and host operations still require project-specific verification. No setup check marks a pack configured, installed, legally approved or deployed.
