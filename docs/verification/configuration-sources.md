# Configuration source verification

Requirements: `REQ-PRODUCT-CONFIG-SOURCES`, `REQ-PRODUCT-CONFIG`.

Package tests compare JSON, YAML and Markdown-frontmatter inputs against the same compiler output and release identity. Markdown-note changes leave public files unchanged. Fixtures exercise YAML 1.2 scalar types, multiline text, literal environment/include-looking values, invalid syntax, duplicate/complex keys, aliases, tags, directives, nonfinite values and input bounds. Reader tests reject symlinks, invalid UTF-8, directories and executable extensions.

Actual CLI tests initialize files without overwriting, validate drafts and production failures, compile public files, assess requested work and import into wizard drafts across all four extensions. The packed core is installed offline without the `yaml` dependency, then its bundled CLI initializes and checks a YAML draft. Browser graph tests confirm that core, headless and consent entry points exclude both the parser and Node reader.

Configuration comments and Markdown notes are authoring material. They are not automatically archived in legal history; policy source archives remain the separate authoring workflow. Browser setup imports and exports the same formats through an optional shared codec. Neither syntax support nor a successful config check verifies the operator's declared facts or legal applicability.

Strict authoring tests reproduce a previously accepted `conset` typo and reject it consistently in JSON, YAML, YML and Markdown frontmatter. Check/build, Node reads, wizard imports, discovery and catalog re-review share the field schema; failed commands leave sources unchanged and create no output. Assessment still produces its structured invalid-config report. Tests retain semantic reference/review checks and ordinary programmatic public projection, permit private JSON metadata, and reject executable/nonplain values before getters or `toJSON` run. Shape diagnostics escape pointer keys, cap large error sets and keep rejected values out of reports. The optional validator bundles for browsers while ordinary core/headless/consent graphs exclude it.

Browser fixtures use actual UTF-8 byte decoding, strict shape errors, YAML/Markdown parsing, local Blob downloads, format switches, matching handoff filenames, source/private-note exclusion and restoration of the saved format. Late format jobs and file reads cannot revive cleared or destroyed exports. CLI output-format tests read each resulting file through the Node reader, verify private file permissions and compare the saved agent brief. Built-site tests import the actual browser codec and its separate parser chunk; default visitor graphs exclude the operator codec. Native browser review covers the actual selection, downloads and mobile layout.
