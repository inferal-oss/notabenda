# Served-document inspection checks

This check compares bounded HTML bytes returned by a fixed host-owned reader with the document selected by a verified retained recording reference. It does not infer publication from an archive or an active pointer. A reader can use an asset binding, so public HTTP routing remains separate.

Tests cover UTF-8 hashes, differences, missing copies, HTTP/media-type failures, omitted cookies and authorization, redirect refusal, byte limits, stalled streams, endless immediately available empty chunks, fetch deadlines, external cancellation, late body disposal, captured settings and generic exception handling. Operator checks require an explicit action, verify their selected scope first, reject destination/path selectors and preserve stored evidence. Installed package types, session-isolated website readers and the generated starter exercise connect the same mechanism.

No response body, response headers or transport exception text is recorded in the result. A matching response describes that reader at that time; it proves no individual permission, enforcement, legal review or lasting deployment state. Host reader implementation and real routing remain acceptance work.

Verified on 2026-10-22:

- 1,386 package tests and 213 site tests passed, including installed TypeScript consumers and semantic accessibility scans of the checked operator cards.
- A subprocess with its own five-second deadline verified that endless empty chunks terminate at the 16,384-read work limit, and that a ten-millisecond deadline still runs. The stream is canceled and no partial hash is returned. Every 64 reads yield a task; empty chunks are not retained.
- The generated Cloudflare starter ran against an actual local asset binding and SQLite Durable Object. Exact, missing and deliberately different responses remained distinct; the selected archive/offer records stayed byte-identical before and after checks and a restart. Fault responses are maintainer fixtures, not scaffolded application behavior.
- Chromium and native desktop Safari exercised the initial unchecked view, explicit checks with eight matching copies, and expandable URL/hash/status references. Safari also exercised the native disclosure using the keyboard.
- The actual local Worker was visually inspected in 390px and 320px Chromium frames. A private proxy permitted same-origin framing for this check; production frame restrictions were unchanged. This is a narrow-screen rendering check, not certification on mobile devices or assistive technology.
- The Cloudflare deployment dry run passed. All 18 measured visitor bundle profiles and all 420 previously retained artifact files were unchanged.

The website reader uses its asset binding. These checks do not demonstrate that a public route or browser received the same response, and do not make the broader deployment or accessibility features complete. Adopters choose whether to run checks manually or in CI.
