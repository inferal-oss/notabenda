# Storage settings localization

The native exception controls select a complete `localization.storageExceptions` dictionary and set explicit language and direction. The shared plain-text validator rejects incomplete, unknown, executable, oversized or placeholder-bearing messages without invoking getters. Entry titles/descriptions, preference retention information and the policy link remain separate host-authored facts. Missing translations fail before the controls attach presentation; a host-owned headless presentation remains possible.

Checks use the actual controller and atomic journal for localized initial, saved, pending, failed, retry and terminal states. Copy-only changes retain the saved entry scopes and objections. Legal releases keep the dictionary, while cookie runtime descriptors and consent notices exclude it. A language never selects or qualifies an exception profile. Pack review and machine-readable integration assessment expose the exact missing dictionary path.

Explicit destruction and synchronous DOM removal leave retained controls inert. Detaching presentation still closes the exception gate without destroying the host-owned controller. Existing English defaults stay available. A Portuguese example uses separate site/storage identities, local mock services and static legal documents; it sends no evidence to the backend and makes no claim of reviewed Portuguese or Brazilian legal coverage.

These checks cover the supported native interface and local example. Full platform, assistive-technology and translated-content review remain open.
